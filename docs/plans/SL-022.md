## Issue
A match's events live in three places, with nothing keeping them in step: the `goals` table, the `matches.scorers/assists/own_goals` JSON, and score columns counted separately.
- The live route:
  - does an unlocked read-modify-write;
  - requires a scorer for every goal;
  - cannot edit a goal (`edit_goal` returns 501);
  - hides drift with `Math.max(0,…)`.
- `/api/matches/update` writes scores after only a sign-in check and has no caller.
- Baseline RLS lets any signed-in user write `matches` and `goals`.
- Walkovers are a 3–0 with no events.
- There are no cards, and no goal without a known scorer.
- Grading reads the JSON and never notices a later correction.

## Evidence
- `backend/app/api/admin/matches/live/route.ts`:
  - `add_goal` ignores errors from the `goals` insert;
  - `add_assist` writes only the JSON;
  - the role check admits `admin`, `dictator` and `captain`.
- Baseline policies give `goals` and `matches` insert/update/delete to any signed-in user (`true`).
- **`season_player_stats`** (`20261124000000`) counts the greater of `goals` and JSON per match and player.
- **Code that depends on that view or on `goals`:**
  - `roster_memberships_keep_history` reads the view;
  - `delete_unplayed_player` reads `goals` (`20261127000000`).
- **Grading:** grade, regrade-all and `predictions/history` compute points from the JSON.
- **The home dashboard** embeds `goals(...)`.
- **Walkovers:** `admin/matches` POST writes a 3–0 walkover. PUT can change the teams of a match that has events.
- **Frontend:** `LiveController.jsx` and `MatchTimeline.jsx` read `goals` directly. `GradePredictions.jsx` drives grading.
- **Seed:** generates `goals` per scoreline and fills the JSON from them. Matches use `ON CONFLICT DO UPDATE SET home_score…`, so a reseed overwrites scores.
- **Columns:** `goals.minute` and `matches.minute` are text.
- **Audit:** `audit_matches` and `audit_goals` are attached (`20261126000000`).
- **Local data:** 446 goals; 119 of 168 matches have JSON scorers; `legacy_player_assist_counts` is empty after a reset.
- **Test groups:** `match-operations` and `fantasy` are pending for SL-022.

## Scope

### 1. Expand migration `<ts>_match_events.sql` (one transaction)

**`match_events` table:**
- `id uuid` PK. The client generates it; the default exists only for server and seed rows.
- `match_id` → matches RESTRICT; `team_id` → teams (the player's own team, own goals included).
- `kind` in `goal`, `own_goal`, `yellow`, `red`.
- Nullable `player_id` and `assist_player_id`, both → players RESTRICT.
- Minute: `minute smallint` (0–150) plus `added_minute`.
- `source` in `live`, `migration`, `seed`.
- `version int`, which a trigger increments.
- `created_by` (default `auth.uid()`), timestamps.
- `voided_at`, `voided_by` and `void_reason`, set together.

**Constraints:**
- An assist only on a `goal`.
- The assister is never the scorer.
- A card needs a player.
- A goal with `player_id IS NULL` is an **unattributed goal**.

**Validation trigger:**
- the team must be in the match;
- the player and the assister must hold a roster place on that team's entry in the match's season;
- `match_id` never changes;
- voided rows and rows on awarded results cannot be edited;
- DELETE is refused for every role, because removal is voiding.

**Version check:** an edit must carry the version the client last saw. The route turns a mismatch into a 409.

**Score cache:**
- An AFTER trigger locks the match row (`FOR UPDATE`) and recomputes the score: home = non-voided home goals + away own goals, and the same for away.
- It also bumps `matches.events_version` and sets the transaction flag `sl.score_writer`.

**Guard (BEFORE INSERT/UPDATE on `matches`):**
- a played match's score changes only with that flag;
- a new match starts at 0–0 unless the result is awarded;
- teams cannot change once events exist.
- Table UPDATE is revoked and re-granted on every column except the score columns and `events_version`.

**Awarded results:**
- `matches.result_kind` in `played`/`walkover`/`forfeit` (default `played`), with `result_reason` required for an awarded result.
- `award_match_result(match, kind, home, away, reason)`: SECURITY INVOKER, dictator only, refused while non-voided goal events exist.

**Grading:** `matches.events_version` and `predictions.graded_events_version`.

**Access:**
- Drop the broad policies on `matches` and `goals`.
- `match_events`: public read; insert and update when `public.can_score(match_id)` (from SL-024: a dictator, or a scorer assigned to the match or its season).
- The same predicate covers clock and status updates on `matches`.
- Revoke anon writes.

**Audit:** attach `audit_row_change()` to `match_events`. Add `events_version` to the noise columns of `audit_matches`, so the score change is still recorded with its actor.

**Backfill (report, do not fix):** results go to `match_event_migration_report`, which dictators read.
1. Each `goals` row becomes an event **with the same id**, source `migration`.
2. JSON-only goals and own goals become attributed events, by the view's per-match, per-player rule. The team comes from the roster place.
3. Any remaining score surplus per side becomes unattributed events.
4. Completed matches with no goal rows or JSON entries are listed as walkover candidates.
5. Unparseable minutes become NULL and are reported.
6. `legacy_player_assist_counts` is reconciled against event assists, and every row is reported.
- **Blockers** (raise and change nothing): more goal rows than the score, a goal for a team not in the match, a scorer with no roster place.
- **Guards:** every goal id exists as an event; every match's recomputed score equals the stored one; the prediction points sum is unchanged.

**`season_player_stats`:**
- Aggregates non-voided events of played matches; goals exclude own goals.
- Keeps its columns in order and appends `own_goals`, `yellow_cards`, `red_cards`.
- Appearances wait for lineups (SL-053).
- Unattributed goals appear in no line.
- `roster_memberships_keep_history` and `delete_unplayed_player` switch to "any event references the player in the season".

### 2. Port every reader and writer
- **`backend/lib/matchEvents.ts`:** validators and the step planner for "+1", "−1" and "set to 2–1" (as event steps).
- **`backend/lib/grading.ts`:** one points function for grade, regrade-all and `predictions/history`.
- **`/api/admin/matches/live`:**
  - `add_event` is idempotent on `id`: a replay returns the stored row, and different content gets a 409;
  - `edit_event` carries the version, and `void_event` voids;
  - `score_step`: −1 voids the newest unattributed goal for that side, otherwise returns a 409 listing the candidate goals;
  - clock and close actions stay;
  - writes run as the caller, so RLS decides, plus an explicit 403.
- **Grading:**
  - the scoreline comes from the score columns, and player points from attributed `goal` events;
  - each graded prediction records `graded_events_version`;
  - a corrected completed match shows "needs regrade";
  - regrading overwrites `points_awarded`;
  - dictator only.
- **Walkovers:** `admin/matches` POST creates the match, then calls `award_match_result` with the awarded score (3–0 as the current default, which the dictator can change; not hard-coded per division) and a required reason. PUT no longer changes teams once events exist.
- **Readers:**
  - standings keep reading the score columns, plus `result_kind` for labels;
  - the dashboard embeds `match_events`;
  - leaderboard, legends and the player pages keep reading the view.
- **Retire `/api/matches/update`.**
- **Seed:**
  - matches start at 0–0, events have source `seed`, and a reseed keeps scores;
  - a canonical fixture season with known standings includes an unattributed goal, an own goal, a voided event, cards and a walkover.
- **Staging checks:**
  - anon and a normal user cannot write events or scores;
  - the cached score equals the events;
  - an assigned scorer can write.

### 3. Minimal UI (rule R10, current patterns)
- **`LiveController.jsx`:**
  - "+1 Home" and "+1 Away" add unattributed goals;
  - an "N goals unattributed" banner;
  - an event list where each row has Attribute/Edit (scorer, assist, minute, own goal, card type) and Void (reason and confirmation);
  - Add card;
  - a picker for which goal −1 removes when none is unattributed;
  - loading, empty, success and error states, per-row busy state, and a clear message on version conflicts.
- **`MatchTimeline.jsx`:**
  - goals, own goals and cards in minute order;
  - "Unknown scorer" for unattributed goals;
  - voided events hidden;
  - a walkover label;
  - loading, empty and error states.
- **`GradePredictions.jsx`:** shows "needs regrade".

### 4. Contract migration `<ts>_retire_legacy_match_events.sql` (same release)
- **Guards:**
  - every goal row has its event;
  - JSON totals are covered by events per match;
  - the cached score equals the events for every played match;
  - every snapshot row is in the report.
- **Then drop** `goals`, `matches.scorers/assists/own_goals` and `legacy_player_assist_counts`. The report table stays.

## Rollback
- **Before the contract migration:** the code can be reverted. `goals` and the JSON are untouched, and the events reuse the goal ids. A forward migration can drop the triggers and restore the previous view body.
- **After the contract migration:** fix forward, using `match_event_migration_report` and the audit log.
- **UI:** each component is its own commit and reverts on its own.
- **Production:** the release goes out only after a backup or PITR point, a clean dry run on a local restore, and the owner's approval of the `main` release.
