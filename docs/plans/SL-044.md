# Plan for SL-044 — Versioned rules page

## Issue

Rules are not data yet. `frontend/src/pages/Rules.jsx` holds two hard-coded sets (the women's set when the division is `wsl`, the men's set for every other division, including any new one), and a season's `seasons.rules_md` replaces them as plain text. A dictator cannot build structured rules, preview them or keep their history, and SL-045 needs the exact version a player accepted.

## Scope

1. **Migration `20261207000000_season_rules_versions.sql`** (forward-only):
   - **Blocks:** a jsonb array of `{id, type, hidden, ...}`:
     - `section` (title, body?, items?);
     - `callout` (title, body, tone `eligibility` or `info`);
     - `steps` (title?, items);
     - `table` (title?, columns, rows matching the column count);
     - `notice` (tone `info` or `warning`, body).
     `rules_blocks_valid(jsonb)` checks types, required fields, lengths, at most 100 blocks and unique ids, and is a CHECK on both tables.
   - **`season_rules_drafts`:** one per season, dictator-only.
   - **`season_rules_versions`:** numbered per season, immutable (a trigger refuses update and delete), readable by dictators only. A version holds the visible blocks only, so it is exactly what visitors saw.
   - **Audit:** `audit_row_change()` on both tables.
   - **Functions:** `save_rules_draft`, `publish_rules` (locks the season, refuses an empty or unchanged draft), both SECURITY INVOKER with an explicit `is_dictator()` check; `season_rules` (SECURITY DEFINER) returns only the latest version of a public, unarchived season in a public division with the rules section enabled.
   - **Backfill, repeatable and verified in the migration:** a season with `rules_md` gets version 1 holding that text; otherwise the `wsl` seasons get the women's set and the `super-league` and `freshers` seasons the men's set (what visitors see today). Other divisions get none and show the empty state. The draft starts equal to version 1. The migration fails on a count or text mismatch.
2. **Contract migration `20261207000001_retire_rules_md.sql`:** drops `seasons.rules_md`, committed only after the backfill is verified locally and on staging.
3. **Worker routes** (caller-scoped, `api/src/seasonRules.ts`):
   - public `GET /rules?division=&season=`, scoped like the other public reads; block validation stays in the database only;
   - dictator `GET /admin/seasons/:id/rules`, `PUT .../rules/draft`, `POST .../rules/publish`, `GET .../rules/versions/:version`;
   - registered in `docs/contracts/worker-compatibility.md`.
4. **Public page:** `Rules.jsx` renders the published blocks with loading, empty ("Rules have not been published for this season yet.") and error states. The hard-coded sets and the `rules_md` reader are removed.
5. **Dictator editor** (`ManageRules.jsx` in the season detail, existing patterns, no redesign): block list with add, up and down, hide and delete; one selected block editor; draft status; separate Save draft, Preview (the visitor presentation, labelled as a preview) and Publish; version history opening a read-only version.

A player's view of the accepted version arrives with SL-045, which stores the version id.

## Acceptance checks

C1 (owner) holds when these pass, locally and on staging, through the real dictator UI, Worker and public page:

1. Migrated rules read as before; the `rules_md` reader and field are retired after that verification.
2. Titled sections, eligibility callouts, numbered steps, tables and notices can be assembled, reordered and hidden without deleting; preview shows them as a visitor would.
3. Publishing is audited; editing a new draft changes nothing for visitors; after publishing again the previous version is unchanged and readable by the dictator. Non-dictators cannot write or read drafts and history.

## Tests

- **pgTAP** `027_season_rules.test.sql`: validity, immutability, version numbering, hidden blocks left out, draft edits invisible, hidden or archived season and disabled section return nothing, non-dictators refused, backfill result.
- **Worker integration** `backend/tests/divisions/season-rules.integration.test.ts`: dictator allowed with the audit actor checked; captain, scorer, editor, normal user and visitor refused with nothing stored; invalid blocks 400; public route returns the latest only, in at most 3 rounds.
- **Frontend:** component tests for the editor and the block rendering.
- **R10:** `scripts/ui-walkthrough/rules.mjs` with `--target local` and `--target staging`.

## Rollback

- The first migration is additive; older code ignores the new tables.
- The contract migration removes a column the previous site reads, so it ships only after the new pair is verified. Rolling back past it needs the column added again from version 1 of each season ([pair procedure](../rollback/pages-worker-pair.md)).

## Assumption

Freshers keeps the men's rule set it shows today; the dictator edits it afterwards.
