# Plan: audit RLS, security-definer functions and service credentials

**Status: draft (2026-11-18).** SL-025 starts only after SL-021, SL-042, SL-024, SL-022 and SL-027 are done, and audits the final Phase 2 schema. SL-024 and SL-022 already close the `matches`, `goals`, `teams` and `newsletter` write policies, the live route's captain branch, dictator-only grading and `/api/matches/update`. This item only verifies those.

## Issue
- **Over-broad grants:** the baseline grants anon and authenticated `ALL` on every table, function and sequence, and its default privileges do the same for every future object.
- **Definer functions:** some have `search_path=public` and anon EXECUTE.
- **`user_profiles`:** exposes `email` to everyone, and a user can rewrite any column of their own row.
- **Middleware:** `PATCH` is not covered by the session check.
- **World Cup:** the flair route writes any profile with the secret key and no authentication.
- **Cron routes:** some fail open, and two have no check at all.
- **No guard:** no test stops a new table, function or grant from reopening any of this.

## Evidence
Queried read-only on the local stack, 2026-11-18.
- **Default privileges:** `pg_default_acl` for `postgres` (and `supabase_admin`) grants all table privileges and function EXECUTE to `anon` and `authenticated` (baseline, end of file).
- **Anon table privileges:** anon holds INSERT, DELETE and **TRUNCATE** on `goals`, `matches`, `newsletter`, `predictions`, `teams`, `team_registrations`, `user_profiles`, `user_roles`, all `wc_*` tables and the security-invoker views. TRUNCATE bypasses RLS.
- **Signed-in users held TRUNCATE on the SL-020/021 tables too.** The Data API cannot issue TRUNCATE, so this is defence in depth rather than a reachable hole; it was revoked on 2026-11-18 in `20261127000000` for the division, season, roster and player tables. Every other table still needs the sweep.
- **Definer functions with anon EXECUTE and `search_path=public`:** `enforce_college_domain`, `handle_new_user`, `get_user_role`, `is_role_manager`, `handle_new_user_role`. SL-024 drops the last three.
- **`user_profiles` policies:** SELECT `USING (true)`; UPDATE `USING (auth.uid() = id)` with no `WITH CHECK`.
- **Readers of `email`:**
  - `ManageRoles.jsx`, `AuditHistory.jsx`, `ManageRegistrations.jsx` (if it survives SL-024);
  - `AuthContext.jsx` (`select('*')`);
  - `Onboarding.jsx`, whose upsert writes `email`;
  - `api/predictions/leaderboard`, which falls back to the email's local part for display names.
- **Middleware:** `backend/middleware.ts` only checks POST, PUT and DELETE. The only PATCH route is `api/wc/flair`, which trusts the body's `user_id`.
- **Cron routes:**
  - `wc/sync/{groups,matches,players,teams}` compare against `` `Bearer ${CRON_SECRET}` ``, so an unset secret accepts `Bearer undefined`;
  - `wc/sync/single` and `wc/grade/*` read the secret from `?auth=`;
  - `wc/sync/{manual,brazil}` have no check at all.
- **`20261106180125_harden_roles_and_rpc.sql`** is empty and already applied, so it must stay byte-identical.

## Scope
### 1. Expected matrix (data file)
`backend/tests/security/access-matrix.json`, derived from SL-003.
- **Roles:** anon, normal, captain (own team / other team), scorer (assigned / unassigned / expired), editor, dictator.
- **Per table:**
  - for each role and each of select/insert/update/delete: `all | visible | own | assigned | none`;
  - `rls: true`;
  - `audit: required | exempt:<reason>`;
  - the expected grants to anon and authenticated, with column lists for `user_profiles`.
- **Per definer function:** a pinned `search_path` and the roles allowed to EXECUTE.
- **Audit exemptions:** `predictions` (volume; points are recomputable), `wc_*` (isolated domain), `division_flairs` (cosmetic), `legacy_*` (read-only snapshots), and `audit_log` itself.

### 2. Inventory test (generated from the catalog)
`backend/tests/security/inventory.test.ts` reads the local catalog, like `schema-inventory.test.ts`. It fails when:
- a public table or view has no matrix entry;
- a table has RLS off;
- a definer function is unlisted, unpinned, or executable by anon or PUBLIC without being listed;
- a `postgres` default ACL grants anything to anon or authenticated;
- a table grants TRUNCATE, REFERENCES or TRIGGER to anon or authenticated;
- anon has any write privilege;
- an audit-required table lacks the audit trigger.

Tests come first. Holes that are still open sit in a `knownHoles` list that the test asserts **still fail**; the fix commits empty it.

### 3. Forward migration `<ts>_rls_definer_and_grant_hardening.sql`
The empty file stays byte-identical, and a tooling test pins it.
- **Default privileges:** `ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public REVOKE ALL ON TABLES, FUNCTIONS, SEQUENCES FROM anon, authenticated, PUBLIC`. The `supabase_admin` defaults cannot be altered by `postgres`; they are recorded as a platform exemption, and per-object checks cover their effect.
- **Tables:** revoke TRUNCATE, REFERENCES and TRIGGER from anon and authenticated, and every anon write. Grant back exactly what the matrix lists; RLS stays the row rule.
- **Functions:** revoke EXECUTE from PUBLIC and anon on all public functions, then grant back the allow-list. Repin `enforce_college_domain` and `handle_new_user` to an empty `search_path` with qualified names.
- **`user_profiles`:**
  - column SELECT on `id, real_name, nickname, team_flair_id, wc_team_flair, created_at`;
  - column UPDATE on `nickname, real_name, team_flair_id, wc_team_flair`;
  - the update policy gets `WITH CHECK (auth.uid() = id)`;
  - inserts allowed for the own row only, with `email = auth.email()`;
  - `dictator_account_directory(ids)` (definer, dictator only) for emails;
  - `public_display_names(ids)`, which keeps today's fallback without exposing email.
- **Audit completeness:** attach the audit trigger to every audit-required table not yet covered: expected `teams`, `newsletter`, and `user_profiles` with `email` private.

### 4. Port readers first
- The role-management and audit views use `dictator_account_directory`.
- `AuthContext.jsx` selects explicit columns and takes the user's own email from the session.
- `Onboarding.jsx` updates its own row without email and sends the token to `wc/flair`.
- The predictions leaderboard uses `public_display_names`.

### 5. Routes and credentials
- **Middleware:** PATCH joins the mutation set.
- **`wc/flair`** (narrow, isolated World Cup change; the page, behaviour and data are unchanged): authenticated only, updates the caller's row under RLS, 403 on a different `user_id`, no secret key.
- **Cron guard:** `backend/lib/auth/cron.ts` `requireCronSecret`:
  - constant-time compare;
  - refuses when `CRON_SECRET` is unset;
  - accepts a Bearer token, and `?auth=` for compatibility.

  It applies to all `wc/sync/*` (including `manual` and `brazil`) and `wc/grade/*`.
- **Key downscoping** (per `docs/supabase-key-usage.md`):
  - grading runs as the calling dictator;
  - `wc/flair` uses the publishable key;
  - the World Cup prediction submissions take the user from the token, with 403 on a mismatch.
  - Each remaining secret-key file gets a guard classification (`cron | dictator | caller-verified | public-read`), and the key-usage test asserts the guard runs before the client is created.

### 6. Out of scope
- Re-closing what SL-024 and SL-022 close (verified only).
- The World Cup data model (SL-043).
- Rotating secrets (Phase 3).
- **R10: not applicable.** This is a security change; existing flows are covered by the regression groups.

## Rollback
- **Forward-only migration:** a defect is fixed by a further forward migration that re-grants a specific privilege; the baseline's broad defaults are never restored.
- **Readers port first:** they work before and after the revoke, so code commits revert independently.
- **Cron and flair guards:** revert per commit; World Cup behaviour is unchanged either way.
