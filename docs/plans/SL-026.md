## Scope

Produce one document at `docs/contracts/worker-compatibility.md`, labelled with the source commit. Use two tables and a short list of migration risks.

- **Mounted Worker surface.** Start with the route table and add health and local-only media from the Worker app. Group methods where the caller and access rule match. For each operation, record the caller, method and path, request inputs, frontend-consumed response fields or content type, access category, and what Phase 3 must preserve. Link the handler and existing tests where available. Use a short disposition note for relevant unmounted and retired paths.
- **Direct Supabase dependencies.** Group distinct operations by access rule. Cover Auth/session handling, public reads that must remain available, and account-scoped or privileged operations Phase 3 needs to preserve or explicitly hand off. Record the caller or helper, table or RPC, inputs and consumed result, access category, and whether the operation stays direct or moves in an existing backlog slice. Skip repeated call sites, field-by-field schemas and static UI.
- **Migration risks.** Call out same-origin bearer forwarding, division and season defaults, caller-owned writes and private profile fields, scoped captain/scorer permissions, and protected browser calls that rely on RLS or RPCs. Keep the [World Cup archive on `/wc`](../decisions/D-02-world-cup-separation.md) with its existing deadlines and navigation. Record polls and `freshers_fixtures` as retired and Freshers registration as SL-045.

Feature work, new API versions or adapters, data changes, latency work, storage changes, Next retirement and redesign belong to their existing backlog items. Preserve existing application code, migrations, permissions, configuration and decision records.
