## Assumptions and deviations

- The public route is `GET /rules?division=&season=`, scoped like the other public reads.
- Only the database validates blocks; the Worker does not repeat the rules.
- Freshers seasons keep the Super League rule text they showed before; the dictator can edit it.
- A backfill function runs from the seed too, because seeded seasons are created after migrations.

## Risks and follow-ups

- A production release must serve the new site before the migrations run: the previous site reads `rules_md`.
- The first staging run, just after the first deploy, timed out once waiting for version 2 on the public page. The next two runs passed; the cause was not confirmed.
- Each staging walkthrough leaves one season in the archived `sl-check-rules` division, because published versions cannot be deleted.
- SL-045 stores the accepted version id and adds the player's view of it.

## Rollback

Restore the previous site and Worker using the [pair rollback procedure](../rollback/pages-worker-pair.md). Rolling back past `20261207000001` needs `seasons.rules_md` added again and filled from version 1 of each season. The rules tables can stay; older code ignores them.
