## Summary

The app now uses Supabase's publishable and secret API keys instead of the legacy anon and service_role JWT keys. Backend routes read them through fail-closed getters, with the silent anon fallbacks removed; the frontend uses the publishable key only; the Pages Function sends the key as an apikey header only; a reviewed list limits which files may use the secret key; and a build guard fails if a private-looking value reaches the frontend bundle.

## Risks and follow-ups

- Revoking the legacy secret may have signed out existing sessions once.
- Any forgotten consumer still using a legacy key (a script, preview environment or integration) will now fail; none appeared in the API logs.
- Keys must be rotated through the dashboard, then the variables updated in Vercel, Cloudflare Pages and the git-ignored local files.

## Rollback

The code change reverts with its commits. The legacy keys cannot be restored after the JWT secret revocation; recovery means creating new keys and updating the variables. Do not copy the staging secret key to Production.
