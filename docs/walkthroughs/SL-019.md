## Summary

The development process used to be Markdown instructions that nothing checked: tests could be skipped by path-based selection, the Git hooks were opt-in with an environment variable that skipped them, there was no Definition of Ready or Done, and the process files were not even tracked. This item replaced that with enforcement. Test groups are now strict (every changed file must be mapped, covered by a group that really has tests, and come with a changed test). The Git hooks install automatically, have no bypass, and a pre-push hook only allows `ready/<name>` branches. The backlog is tracked as one checkable file per item, with a status machine, phase gating, an owner-approved plan before work starts, and a Definition of Done that records evidence and requires a validated walkthrough. A Claude Code guard denies bypasses and the safety limits that were only prose. CI ends in one required `gate` check, a read-only audit verifies it all, and the owner has applied a no-bypass GitHub ruleset that requires it.
