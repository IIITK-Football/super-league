Facts between the generated markers are written by `pnpm work done`; do not edit them. Fill in every other section.

## Summary

A player identity (the reusable FUT card) can now belong to one verified account, and only a dictator controls that link. Auth is the only source of a player's email: a linked player's email is their account's sign-in email (read-only everywhere), and an unlinked player has none. The old dictator-entered contact emails were converted once: each became an outcome with no address, and for unlinked legacy players a private match key used only to find their account.

Dictators match legacy players to verified accounts by exact email (a live preview with ready, waiting, no-account, duplicate and conflict counts, and one action for every ready match), link by hand through Division -> Season -> Team -> Player, and unlink. When an account's email becomes verified, it is linked automatically to the one player waiting for that email, without ever blocking sign-up. Every new player starts from a verified account (an account that already has a player is offered as that player), and only linked players can join a roster. A linked player edits only their own portrait and preferred foot on `/profile`. A player has exactly one play style from the catalog.

## Assumptions and deviations

- The migration evidence keeps no email address (owner's instruction): outcomes and counts only; addresses survive only as match keys of unlinked players.
- Legacy fixtures that the API now refuses (players without an account) are written in tests through a local-only psql helper (`backend/tests/local-fixtures.ts`, 127.0.0.1:54322), the way the seed writes them.
- On staging, the matching apply-all UI test is skipped: match keys cannot be created through the API by design, so the staging fixtures would be used up. It runs locally.
- Found on staging and fixed in the seed: (1) the old seed's contact email became a match key on staging, so the automatic-link fixture address was shared by two players; it now has its own address; (2) seed accounts lacked the Auth instance id and had NULL token columns, so the Auth API could not load or confirm them; the seed now repairs them and a seed check requires it.
- The roster picker for the manual link is a new hook (`useRosterPicker`); Teams & Rosters keeps its own loaders for now.
