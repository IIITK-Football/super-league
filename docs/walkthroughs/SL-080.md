## Summary

Hosted databases are now changed only by `.github/workflows/db-deploy.yml`: a push to `develop` migrates and seeds the staging project (synthetic data only), and a push to `main` applies migrations only, never the seed, to production behind the required reviewer. Before any production migration the workflow takes an encrypted backup, restores it in a disposable stack, and the approval step re-reads the backup and refuses one that is not fresh and verified. The first production release (2026-11-19, Database deploy run 44610257088) applied all 19 pending migrations through 20261130000007 this way.

## Rollback

Production migrations are forward-only. To undo a release, restore from the verified pre-migration backup as described in `docs/backups.md` (owner only), or ship a forward fix. To stop the automation, disable `db-deploy.yml`; nothing else depends on it.
