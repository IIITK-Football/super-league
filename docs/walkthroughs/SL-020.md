## Summary

Divisions and seasons are now data a dictator manages, not code. Super League, WSL and Freshers are ordinary division records, each with a current 2026 season that holds all of its existing data, and any new division (e.g. Inter) or season can be created from the dashboard with no code or schema change.

Everything that depends on a run of a competition belongs to a season:
- team participation and rosters;
- matches and their events;
- standings, statistics and fantasy predictions and points;
- registrations and captains;
- sections and rules text.

Team identity, supporter flairs, legends, news and accounts stay division-wide or global, as recorded in D-01.

The dictator dashboard has a Divisions & Seasons tab to create, edit, archive and configure divisions, seasons and sections. Every league page follows the selected division and season. The homepage shows a season dropdown when a division has several seasons, and `/<division>/<season>` addresses open a season directly. The legacy division-string columns, views and compatibility machinery were retired once every caller was ported, together with the unused polls feature.

## Risks and follow-ups

- **Production run:** the contract and fantasy migrations stop if production data breaks their guards: a real account whose stored points differ from its graded predictions, real polls, or an unattached record. That is by design; resolve the reported rows, then re-run. Take a backup or PITR point before the `main` release.
- **Deploy timing:** the frontend and backend switch from the division strings to slugs together. An old frontend talking to the new API (or the reverse) during the deploy gets 404s for `mens`/`womens` until both are live.
- **Follow-ups recorded in the backlog:**
  - SL-041: the team-entry workflow and the captain-change defect;
  - SL-042: admin player creation writes missing columns and sets no season roster;
  - SL-025: the grading routes check only for a signed-in user;
  - SL-044: configurable rules and page presentation;
  - SL-054: data-driven brackets;
  - SL-091: generic routes for divisions created later.

## Rollback

Forward-repair only. The legacy columns, views, polls and profile points are dropped, so rolling the code back alone does not restore them.
- **Before production:** revert the `develop` commits, and add a forward migration on staging if needed.
- **After production:** restore from the backup or PITR point taken before the release, or write forward migrations that re-derive the old columns from the season model. Every dropped value is derivable: division from season, and points from predictions.
- **Dashboard only:** removing the tab is a single revert of the dashboard commit and touches no data.
