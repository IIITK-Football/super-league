## Summary

Match events are now the single source of truth for what happened in a match. Goals, own goals, yellow and red cards live in `match_events`; the stored score is a cache the database recomputes from the non-voided events in the same transaction, so no client can type a score any more. An assigned scorer (or a dictator) records goals in the Live tab, even before the scorer is known (an unattributed goal, shown as "Unknown scorer" with a banner), and can attribute, edit the minute or own-goal flag, add cards, and void any event with a required reason. Events are versioned, so a stale edit is a 409 instead of a silent overwrite, and a replayed request is idempotent. A walkover or forfeit is an explicit awarded result set by a dictator with a reason. Grading reads events, is dictator-only, and a match whose events changed after grading shows "Needs regrade" instead of silently changing points. The public timeline, statistics, standings, predictions history and home dashboard read events; the retired `goals` table, the match JSON columns (`scorers`, `assists`, `own_goals`), the assists snapshot and `/api/matches/update` are gone.

## Assumptions and deviations

Unattributed goals are first-class (a null scorer) because live scoring must not wait for a name; the score still counts them and no player line does. Removal is voiding, never deletion, so history and the audit trail survive. Awarded results default to 3-0 only as a suggestion; the dictator states the score and a reason. The check `C10` (originally a local jsdom test) became the real-app walkthrough script, in line with rule R10.
