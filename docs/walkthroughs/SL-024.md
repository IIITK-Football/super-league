# Walkthrough: SL-024 Five roles with scoped captain and scorer assignments (full port)

Facts between the generated markers are written by `pnpm work done`; do not edit them. Fill in every other section.

## Summary

Roles are now independent grants (captain, scorer, editor, dictator; a normal user holds none) and captain and scorer powers need a scoped assignment: one captain per team entry, writable while its season is current or upcoming, and scorers scoped to a season or one match with an optional expiry. Only a dictator grants roles and assignments, through database functions that keep the grants in step with the assignments, and every change is audited. Matches, goals, teams and news can now be written only by the roles that own them, which closes the holes where any captain could score any match and any signed-in user could write match data. `team_registrations` is retired after being kept whole as history, changing a captain no longer fails, and the dashboard has Access control, Captains and Scorers screens, a scorer sees only Live Matches, and a captain edits team name, short name, logo and colour (also before a roster exists).

## Assumptions and deviations

Both migrations ship in one release, because the application code and the schema change together. The plan's name-difference table became a whole-registration history table (`legacy_team_registrations`) so the drop is safe even if captains change in between. The per-season season-lifecycle RPC is not added here: write access stops the moment a season is completed or archived (the helper checks it live), and the dashboard calls `refresh_captain_grants` after a status change; a proper lifecycle RPC is SL-040. Branding stays team-level (owner decision). The staging walkthrough was API-level; the click-through ran locally against the same schema.
