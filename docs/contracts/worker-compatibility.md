# Worker API compatibility baseline

Source commit `6f39682f5051f6358ca26aa049e3da212a3f3755`. This document versions the existing API surface and browser dependencies by source commit for Phase 3. The domain names below identify ownership across the current routes and Supabase operations. They introduce no new URL prefix. Use this source snapshot for active-flow parity; the archive and HLS release dispositions are in SL-032.

## Mounted Worker operations

Paths are relative to `/api`. The method list comes from the [route table](../../api/src/routes.ts) and [Worker app](../../api/src/app.ts). Successful JSON reads use `success` and `data` unless the table gives a different shape. **Scope** means optional `division` slug (default `super-league`) and optional `season` slug or UUID (default the division's current season). Keep `400` for malformed scope and `404` for unavailable or missing divisions or seasons. Explicit season lookups stay within the named division. [Scope resolver](../../backend/lib/scope.ts).

## Migration risks

- Forward the original request through the Pages `API` binding, including the bearer token and media `Range` header. Vite uses the same `/api` path locally. The Worker verifies session claims before writes, including PATCH. Individual handlers and Supabase policies still enforce ownership or roles. Preserve the deployed binding's configuration failure response. [Pages API binding](../../frontend/functions/api/%5B%5Bpath%5D%5D.js) · [Browser API helper](../../frontend/src/hooks/useApi.js) · [Worker authorization](../../api/src/app.ts)
- Preserve the server scope defaults and the browser's wait for a resolved season. Check each handler before changing its scope, since team match history already spans seasons and the player card has a separate `season_id` selector. Keep stats and standings tied to the selected season. [League Context](../../frontend/src/context/LeagueContext.jsx) · [Scope resolver](../../backend/lib/scope.ts)
- Keep profile email in Auth and player/account links behind their existing RPCs. Retain caller-owned writes and the distinction between display data, private account data and role-gated directory results. Direct protected calls depend on RLS, column grants and RPC authorization during the port. [Security verification](../walkthroughs/SL-025.md)
- Keep captain writes limited to the writable team entry and scorer writes limited to unexpired match or season assignments. Preserve canonical match events and their derived scores when moving code. [Role capability matrix](../decisions/SL-003-role-capability-matrix.md) · [Live handler](../../backend/app/api/admin/matches/live/route.ts)
- The saved-knockout GET can return saved picks without `initial_bracket` because the shared generator request lacks a bearer. This is recorded as an archive feature issue and is outside the active-flow gate. See [D-02](../decisions/D-02-world-cup-separation.md).
