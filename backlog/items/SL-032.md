**Issue:** Existing Next routes are distributed and not all are covered by contract tests. Removing Next routes before parity would break current pages.

**Required outcome:** Migrate in bounded groups: public division data; match schedule/results; teams/players/standings; user auth/profile; predictions/fantasy; dictator/captain/scorer operations; newsletter/polls; World Cup; media proxy. Keep a route-by-route parity register.

**Completion checks:** Each group passes API contract and authorization tests against local Supabase; existing frontend can continue to use the compatibility surface; cutover and rollback are defined before any production route switch.

**Consolidated (2026-11-18):** the port moves the final Phase 2 model: identity and rosters, accounts, scoped roles and canonical match events. Polls are gone and `freshers_fixtures` never existed in hosted data. Media upload and proxy routes are ported onto the storage interface from SL-071, not onto per-route R2 clients. Every route group keeps its existing frontend flows working (rule R9), verified locally and on staging.

**Usable in its own phase (rule R10):** no new capability. Each ported group keeps its existing user flows working through the real UI, gateway and database path, locally and on staging.
