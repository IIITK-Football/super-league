## Assignment

**Entry point.** Use the local and staging app as a visitor, player, captain, scorer, editor, and dictator.

### Acceptance scenario

1. Verify active route groups against the compatibility register, including current uploads, then confirm scoped failures and rollback evidence. Archive feature bugs and HLS have separate dispositions.

**Disposition: partial.** The [Worker route table](../../api/src/routes.ts) serves shared handlers. The [compatibility baseline](../../docs/contracts/worker-compatibility.md) inventories 44 operations across 33 mounted paths and direct browser dependencies. [Worker tests](../../api/test) cover representative routes; [SL-025](../../docs/walkthroughs/SL-025.md) records limited staging evidence.

### Evidence register

1. Record local and staging pass/fail results for each active contract group: division and season public data, fixture/results/standings, teams/players, account/profile, division predictions, scoped match/roster writes, editorial and current uploads. Run through the actual browser, Worker and Data API as applicable.
2. Check authorized actions, refused requests and absence of state changes on denial. Name any uncovered active route as a gap until its contract is verified. Apply the compatibility baseline to current uploads.
3. Record the compatible Pages and Worker rollback pair. HLS failures belong to [SL-106](SL-106.md). Keep the existing archive URL and data protections under [D-02](../../docs/decisions/D-02-world-cup-separation.md). Archive feature fidelity, including saved bracket rendering, is outside this gate.

**Usable in its own phase (rule R10):** Existing flows need real local and staging evidence for each ported group.
