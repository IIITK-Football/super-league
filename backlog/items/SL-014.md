**Status:** Complete (2026-11-16). Commit `0f5c52c`. tests/groups.json (9 groups, owners), scripts/test-groups.mjs, `pnpm test|test:all|test:group`, CI workflow, docs/testing.md. `pnpm test:all` on the local stack: database, config, tooling, frontend-components pass; 5 groups reported pending with owning backlog items.

**Issue:** No application tests or group-selection convention are tracked. Running an undifferentiated full suite for every edit would be slow and discourage coverage.

**Required outcome:** Define test groups by affected domain (database/migrations, auth/roles, API services, match operations, fantasy, frontend components, end-to-end). Add a small foundation that lets a changed feature run the relevant group while preserving a full scheduled/release run.

**Completion checks:** Test groups have names and clear ownership; each acceptance item later adds relevant tests; CI reports which groups ran; test data uses the local Supabase environment or isolated test fixtures.
