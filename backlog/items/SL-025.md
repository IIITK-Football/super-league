**Consolidated (2026-11-18):** the audit history moved to its own earlier item (SL-027). This item audits the final Phase 2 schema, after the identity, account, role and match-event slices, so it is done once.

**Issue:**
- The baseline has broad authenticated write and delete policies and overlapping policy sets.
- Several APIs use privileged keys independently.
- Known holes remain open (below).

**Required outcome:**
- Review every table, function and route authorization path.
- Eliminate public and anonymous privilege escalation.
- Set a safe `search_path` and execute grants for definer functions.
- Scope service-role operations.
- Close the known holes. Keep the World Cup fix narrow and isolated, with no change to the World Cup page or user-visible behavior.
- Fill the currently empty hardening migration only after the tests are designed.

**Completion checks:**
- Automated negative and positive permission tests cover all role/entity/action combinations and direct Data API paths.
- Privileged keys are server-only, and no API silently falls back to a weaker or wrong key for privileged operations.
- Every sensitive table writes the SL-027 history.
- The migration applies to a reset local database reproducibly and on staging.

**Usable in its own phase (rule R10):** not applicable. This is a security change with no new user-facing capability. Existing flows keep working and are covered by the regression groups.

**Known holes:**
- *Found during SL-020 (2026-11-19):* `POST /api/admin/predictions/grade` and `regrade-all` check only that the caller is signed in, not that they are a dictator. Any account can trigger grading.
- *Found during the 2026-11-18 restructure:*
  - `PATCH /api/wc/flair` has no authentication at all and updates any `user_profiles.wc_team_flair` with the secret key.
  - `user_profiles` is publicly readable, including `email`, and its own-row update policy has no `WITH CHECK`, so a user can change any column of their profile, including email.
  - `backend/middleware.ts` requires a session only for POST, PUT and DELETE, not PATCH.
