**Issue:** The baseline has broad authenticated write/delete policies and overlapping policy sets. One extended captain security-definer RPC does not visibly enforce the same ownership check as the constrained overload. Several APIs use privileged keys independently.

**Required outcome:** Review every table/function/route authorization path; eliminate public/anonymous privilege escalation; set safe `search_path` and execute grants for definer functions; scope service-role operations; add an attributable, append-only audit history for sensitive role, account-player link/unlink, registration, score/event, and division-configuration changes. Record actor, action, target, time, and a safe before/after summary without logging secrets. Fill the currently empty hardening migration only after tests are designed.

**Completion checks:** Automated negative and positive permission tests cover all role/entity/action combinations and direct Data API paths. Sensitive changes have a durable actor/time history visible to dictators; history cannot be silently edited by the actor being audited. Privileged keys are server-only and no API silently falls back to a weaker/wrong key for privileged operations. Migration can be applied to a reset local DB reproducibly.
