**Added (2026-11-20):** deferred from the staging R2 binding work, which was limited to the upload paths (portraits, team logos, news images). Part of the release-candidate slice, after the player self-service card (SL-104), which shows play styles.

**Issue:** `frontend/src/data/playStyles.js:1` hard-codes `IMAGE_BASE = 'https://pub-44b1a3890e2b40c4836f3a3c8e18f090.r2.dev'` (the production `playstyles` bucket). Every play-style icon on FUT cards, rosters and the dictator and captain forms loads from production, including on staging and locally, and changing the host needs a code change (rule R8).

**Required outcome:**
- The icon base comes from per-environment configuration (D-06 `MEDIA_BASE_PLAYSTYLES`): a staging base for staging, a local base for local development, and the production host only in production.
- The play-style catalog (names and file names) stays in code; only the host moves.
- Icons are still loaded straight from the public bucket URL, never through the API or Pages.
- Copying the icons into a staging bucket is not part of this item unless the owner approves it. Until then, staging may read the production public icons through configuration (read-only), as the home video does.

**Completion checks:**
- No `r2.dev` or production media host remains in `frontend/src/data/playStyles.js` or anywhere else in `frontend/src` (a source scan test fails if one is reintroduced).
- Each catalog play style resolves to `<configured base>/<file>`, tested.
- On staging, the FUT card shows each play-style icon from the configured base; a missing setting shows the documented fallback instead of a broken image.

**Usable in its own phase (rule R10):** no new capability; the existing card and forms keep showing the icons, verified on staging.
