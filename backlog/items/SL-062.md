**Issue:** `frontend/functions/_middleware.js` hard-codes quarter-final and semifinal descriptions and points to fixed R2 assets.

**Required outcome:** Store match-share title/description/image configuration with match or division content, including quarter-final, semifinal, final, and other stage-specific variants. Have the Pages/Worker metadata response use that approved source and support safe fallback metadata.

**Completion checks:** Updating a match or its share image does not require a GitHub screenshot workflow/code edit; public previews have a tested cache strategy and cannot expose private data.

**Usable in its own phase (rule R10):** this item is not complete until a dictator edits the match-specific share content, and the shared link shows it. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
