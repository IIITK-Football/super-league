**Issue:** The user wants external platform APIs for schedule and match scores, but no provider contract, reliability policy, or conflict precedence is defined.

**Required outcome:** Evaluate and specify provider adapter(s) for match schedule and score only; Be.tech was named as an example, not a committed provider. Define manual scorer precedence, update cadence, provider attribution, duplicate prevention, error handling, and whether imported events require confirmation.

**Completion checks:** External data cannot overwrite an authorized manual correction silently; imports are idempotent and logged; one provider can be replaced without changing division core models.

**Usable in its own phase (rule R10):** if an import needs a person to confirm, review or resolve a conflict with a scorer's edit, this item delivers that minimal flow in the existing frontend (real authorized action; loading, empty, success and error states; UI-to-API-to-database test). A fully automatic adapter with no human step needs no UI.

**Consolidated (2026-11-18):** imports write the canonical match events (SL-022) and respect the scorer workflow and its conflict handling (SL-050).
