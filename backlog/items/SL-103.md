**Consolidated (2026-11-18):** the dictator-managed sign-in allowlists were split out to SL-047 (Phase 4) by owner decision, because they are an account capability with a dictator UI. This item keeps Google One Tap, which is a sign-in presentation change. It is still scheduled after the division/season unification (SL-091); do not start it earlier.

**Issue:** Sign-in relies on Supabase's OAuth redirect flow. A smoother Google flow is wanted once the unified division experience exists.

**Required outcome:**
- Add Google's official Sign in button plus One Tap, using Supabase ID-token sign-in, with `iiitkottayam.ac.in` as the account-selection hint.
- Keep the button available when One Tap is suppressed.
- The SL-047 allowlists apply unchanged.
- Preserve existing users, sessions and account data. Keep OAuth secrets out of Git.
- Coordinate with SL-075, since ID-token sign-in changes which domain Google displays.

**Constraints:** Test Google sign-in only against local or isolated non-production Auth. A Git `develop` branch is not an isolated Auth environment, and production is never a test target.

**Completion checks:**
- The button and One Tap both work and follow the SL-047 rules.
- Rejected accounts see a clear message.
- No secrets are in the repository.
- Existing accounts keep their user ids.
