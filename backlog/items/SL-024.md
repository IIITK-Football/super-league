**Issue:** `admin` currently acts as scorer in labels but receives broad management permissions; editor is an extra legacy role; direct database policies are broader than the intended user capability boundaries.

**Required outcome:** Define role assignments with scope (division/season/team as appropriate), the dictator's assignment authority, and explicit capability checks for normal user, captain, scorer, editor, and dictator. Remove the ambiguous `admin` alias through a reviewed migration (`editor` becomes the newsletter-only editor role; `admin` maps to user unless a reviewed per-person assignment is recorded before migration). CLAUDE.md role count already updated to five.

**Completion checks:** Database policies, API checks, and UI capability decisions agree. A normal authenticated account cannot write match data; a captain cannot create, remove, rename, or otherwise manage player records; scorer can operate all assigned match fields but cannot change division configuration, role assignments, news, roster administration, or predictions grading; dictator can manage all product data and settings.
