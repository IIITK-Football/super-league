**Issue:** A player's card, email, image, attributes, and team membership are not a reusable identity, and a user cannot reliably own their player identity across competitions.

**Required outcome:** Implement verified account-to-player linking, self-service profile/image/FUT editing, reusable FUT presentation data, and division-specific supported-team/nickname preferences stored with that division's fantasy profile. Add dictator-only link and unlink actions to the dictator dashboard. Link by selecting a player identity and a verified Supabase Auth account; store the Auth user UUID, never an email-based foreign key. Unlinking clears only the account association and preserves the player identity, roster participation, statistics, and history. Keep bulk email-to-account mapping as a validated import keyed by stable player IDs, separate from schema migrations; report missing, duplicate, and ambiguous matches for human resolution before applying.

**Completion checks:** One player identity appears consistently in team rosters, match events, lineups, score leaders, and fantasy; only a dictator can link or unlink accounts in the dashboard; linking selects a verified Auth user and enforces one player identity per account; unlinking does not delete or reset player data; unlinked players remain supported; a player can update only permitted self-owned profile fields; historical stats remain attached after transfers; bulk imports never auto-resolve ambiguous names.

**Usable in its own phase (rule R10):** this item is not complete until a player edits their own permitted profile/FUT fields, and a dictator links and unlinks a player identity and an account, from the existing profile page and dictator dashboard. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
