**Consolidated (2026-11-18):** section, navigation and module configuration moved to SL-040. This item is the rules builder. It replaces the Markdown `seasons.rules_md` that SL-020 introduced, and that column is retired here once its content is migrated.

**Issue:** Rules are a Markdown text per season. There is no draft/publish step, no preview, and no version a registration can acknowledge.

**Required outcome:**
- Build the rules page from a library of premade visual components, for example titled rule sections, eligibility callouts, numbered steps, tables and highlighted notices.
- Dictators choose which components appear, enter content through structured fields, and control their order and visibility. Do not require Markdown authoring.
- Provide draft and publish states, a player-facing preview, and version history, so changes never rewrite a previously accepted version.
- Migrate the existing `rules_md` content into the new model, then retire the column and its readers.
- Record every publish in the SL-027 history.

**Completion checks:**
- Dictators can assemble a polished rules page from premade components without writing markup.
- Drafts can be previewed before publishing.
- A published rules version remains available for registration acknowledgments (SL-045).
- The public page follows the selected order and content.
- Hiding a component is reversible.
- No reader of `rules_md` remains.

**Usable in its own phase (rule R10):** this item is not complete until a dictator edits, previews and publishes rules from the dictator dashboard, and visitors see the published result. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
