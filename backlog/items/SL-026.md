**Issue:** API routes expose route-specific response shapes and multiple World Cup/league-specific namespaces. Frontend code relies on those shapes and currently performs some direct Supabase queries.

**Required outcome:** Specify versioned contracts and domain boundaries for accounts/roles, divisions/seasons, teams/players, matches/events, standings/statistics, fantasy, editorial/home presentation, and media metadata. Mark which data is public, account-scoped, or privileged.

**Completion checks:** A route inventory maps every current endpoint and direct Supabase call to a target contract, authorization rule, and migration status; compatibility requirements for the existing frontend are explicit. The parity inventory includes the existing home dashboard, schedules/results, standings, teams/rosters/team builder, profiles/onboarding, match timeline, predictions/fantasy, leaderboards, polls, newsletter/articles, legends/archive, rules, World Cup predictions, role administration, and Freshers registration/fixtures. Public browser access is limited to intentionally public data and Supabase Auth/session behavior; protected writes and role decisions follow the shared Worker/API authorization model.

**Note (SL-020, 2026-11-19):** the public API now names a division by slug and a season by slug or id (`?division=wsl&season=2027`, default the current season; `backend/lib/scope.ts`). The unused polls routes and tables were removed, and `top_scorers`, `league_standings` and `league_schedule` were replaced by `season_player_stats`. The route inventory starts from that state.
