## Assignment

**Entry point.** Dictator opens Stages and Brackets. Visitor opens the season's competition view.

### Acceptance scenario

1. Configure all three formats, remap a fixture, validate tied matches and penalties, then record a correction that conflicts with a played downstream match.

**Consolidated (2026-11-18):** absorbs SL-023 (the stage/format model and editable bracket mapping), so the model, the calculation and the usable flows ship together. It also takes the league/knockout switch that SL-091 used to require, as a usable flow in the existing pages.

### Flow and screen sketch

- Dictator → season → Stages and Brackets → stage format, advancement rules, slot source and match mapping → review an advancement conflict.
- Visitor → season competition view → available league and knockout stages.

### Correction and advancement cases

1. When a corrected result changes a downstream slot before play, recompute advancement without dropping manual mapping. If the downstream match already has recorded play, preserve its result and history and flag the mismatch with the expected qualifier for explicit dictator review.
2. Reorder fixtures and verify slot mappings remain stable. Verify ties, separate penalties, pending results, and permission denials.

**Issue:**
- There is no general stage model for league-only, knockout-only or combined competitions; `seasons.format` from SL-020 is only a label.
- Existing bracket behavior is competition-specific (for example the knockout table special case in `Home.jsx`), and match ordering cannot safely determine a team's bracket slot.

**Required outcome:**
- **Stages:** configurable stages per season with advancement rules, and a league-to-knockout transition.
- **Bracket mapping:** explicit, editable mapping of real matches to bracket slots, or of a slot to a source slot ("winner of QF1").
- **Results:** seeding and tie-break rules, and penalty outcomes recorded with the canonical match result (SL-022).
- **Calculation:** compute league standings and the configured advancement. Regenerate downstream slots without destroying manual mapping. Stage progression never depends on row insertion order.
- **Port:** replace the format-specific frontend branches with data from this model and remove them.
- **Audit:** record mapping changes in the SL-027 history.

**Completion checks:**
- The model represents league-only, knockout-only and combined formats.
- A dictator can map and re-map a scheduled match to a bracket position.
- Standings and advancement can be recomputed and audited.
- Bracket tests cover ties, penalties, missing or unplayed results, result corrections, all supported formats and dictator edits.
- Bracket state stays stable when matches are reordered.
- No format-specific frontend branch remains.

**Usable in its own phase (rule R10):** this item is not complete until all of the following work in the existing pages:
- a dictator configures a season's stages and maps and re-maps matches to bracket positions;
- visitors see the bracket and, when a season has both league and knockout stages, switch between them, with no misleading switch when only one stage exists.

The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
