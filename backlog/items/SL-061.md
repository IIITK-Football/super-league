**Consolidated (2026-11-18):** absorbs SL-062 (moving match-specific Open Graph content out of Pages code). The share target, the copy and the preview metadata are one configuration and one flow.

**Issue:**
- `frontend/functions/_middleware.js` hard-codes quarter-final and semifinal descriptions and points to fixed R2 assets.
- Open Graph and match messaging rely on fixed paths, names and images.
- The requested WhatsApp link should resolve predictably to the live or upcoming match.

**Required outcome:**
- **Target rule:** a dictator selects or configures the target-match rule: explicit assignment, otherwise the active live match, otherwise the next scheduled match. Define a fallback for when no match is available.
- **Content:** store share title, description, message text, image and destination with the match, stage or division content. Include stage-specific variants (quarter-final, semifinal, final and others) from the SL-054 stages. Images are uploaded through the Phase 3 storage system.
- **Metadata:** the Pages/Worker metadata response reads this approved source, with a safe fallback and a tested cache strategy, and never exposes private data.
- **Port and audit:** remove the hard-coded content from `_middleware.js`. Record changes in the SL-027 history.

**Completion checks:**
- Share-link resolution is deterministic across zero, one and several live matches.
- Content is editable without a code change or a screenshot workflow.
- Link preview metadata agrees with the selected match and published image.
- Public previews cannot expose private data.
- No match-share text remains hard-coded (rule R8).

**Usable in its own phase (rule R10):** this item is not complete until a dictator configures the share target, copy and match-specific preview content from the dictator dashboard, and the match share action and the shared link's preview use them. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
