## Assignment

**Entry point.** Dictator edits Share settings. A visitor opens a division share link and sees its WhatsApp preview.

### Acceptance scenario

1. Exercise pinned, multiple live, upcoming, no-match, and hidden-match cases and verify the chosen target and public metadata agree.

**Consolidated (2026-11-18):** absorbs SL-062 (moving match-specific Open Graph content out of Pages code). The share target, the copy and the preview metadata are one configuration and one flow.

### Screen sketch

Dictator → Share settings → pinned fixture, title, message, image and preview → publish. Visitor follows the division share link and sees matching destination and preview content.

**Issue:**
- `frontend/functions/_middleware.js` hard-codes quarter-final and semifinal descriptions and points to fixed R2 assets.
- Open Graph and match messaging rely on fixed paths, names and images.
- The requested WhatsApp link should resolve predictably to the live or upcoming match.

**Required outcome:**
- **Target rule:** a dictator selects or configures the target-match rule: explicit assignment, otherwise the active live match, otherwise the next scheduled match. Resolve within the link’s division: a valid pinned match, the earliest-started live match, the next scheduled match, then the division fixtures. Break equal timestamps by stable match ID. Exclude hidden, archived and inaccessible matches.
- **Content:** store share title, description, message text, image and destination with the match, stage or division content. Include stage-specific variants (quarter-final, semifinal, final and others) from the SL-054 stages. Images are uploaded through the verified storage paths from SL-071 and SL-106.
- **Metadata:** the Pages/Worker metadata response reads this approved source, with a safe fallback and a tested cache strategy, and never exposes private data.
- **Port and audit:** remove the hard-coded content from `_middleware.js`. Record changes in the SL-027 history.

**Completion checks:**
- Share-link resolution is deterministic across zero, one and several live matches.
- Content is editable without a code change or a screenshot workflow.
- Link preview metadata agrees with the selected match and published image.
- Public previews cannot expose private data.
- No match-share text remains hard-coded (rule R8).

**Usable in its own phase (rule R10):** this item is not complete until a dictator configures the share target, copy and match-specific preview content from the dictator dashboard, and the match share action and the shared link's preview use them. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.

**Hard-coded media host to replace (added 2026-11-20, deferred from the staging R2 binding work):**
- `frontend/functions/_middleware.js:112` `IMAGE_BASE = "https://pub-5fcbf3326b604a8284068a24252f1585.r2.dev"` (the production `screenshot` bucket) builds every page's Open Graph image URL.
- Required: the Pages Function reads the image base from per-environment configuration (a Pages variable or the share configuration). It is never hard-coded, and staging previews never point at production screenshots. Pages keeps no R2 binding; the image is a public bucket URL.

**Completion checks for this host:**
- No `r2.dev` or production media host remains in `frontend/functions/` (a source scan test fails if one is reintroduced).
- On staging, a page's `og:image` resolves to the configured staging base and returns an image; with the setting missing, the preview falls back safely without breaking the page.
