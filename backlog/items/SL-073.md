## Assignment

**Entry point.** Owner approves a specific production bucket cutover after staging rehearsal.

### Acceptance scenario

1. Reconcile counts, checksums, references and reachable URLs before switching. Rehearse restore and retain originals through the rollback window.

**Disposition: partial.** [Wrangler configuration](../../api/wrangler.jsonc) and the [staging media check](../../scripts/staging-media-check.mjs) cover the three upload purposes. The [screenshot workflow](../../.github/workflows/og-screenshots.yml) already restricts uploads to `main`. Custom domains, object and URL reconciliation, credential scope and completed cutover still need evidence.

Staging media preparation and playback verification belong to [SL-106](SL-106.md). This item uses that evidence for the owner-approved production cutover. Retain the existing objects and compatible rollback pair.

**Owner direction (2026-11-19):** use `superleague.dpdns.org` for R2 media hostnames; keep the website on Pages.dev. Keep existing production bucket names where their purposes still fit; use environment-specific names for local and staging. Move all objects from `fresher-images` into the canonical `player-images` purpose, verify objects and every caller/reference, switch reads and writes, then deprecate `fresher-images`. Do not empty or retire the source bucket until reconciliation passes and its rollback/retention window has elapsed. Give each directly served public bucket a distinct media subdomain; keep `backup` private with no public hostname. Player portraits are shared identity assets and use one key, `players/<player-id>.png`, regardless of a player's division, season, or team.

**Added (2026-11-20, from SL-100):** the screenshot job (`og-screenshots.yml`, fixed and green since 2026-11-17) must upload only from `main`, to the screenshot bucket, so a dispatch from another branch never writes to production R2. The branch restriction is implemented. Bucket scope and migration verification remain.

**Issue:**
- Bucket names and public URLs are hard-coded or documented inconsistently.
- Media URLs are stored in database rows.
- Disabling the old hosts immediately would break current production media.

**Required outcome:**
- **Final layout (D-06):** preserve existing production bucket names where they still match their purpose; use `sl-local-*` and `sl-staging-*` names for non-production. `fresher-images` is a temporary migration source; move its contents to `player-images`, then deprecate it only after verified cutover and rollback retention. Keep other purposes separate unless SL-070 finds a safe, evidenced reason to consolidate.
- **Custom domain:** configure `superleague.dpdns.org` for R2 media only; the website stays on Pages.dev. Use one host per directly served public bucket (for example, `media-player-images.superleague.dpdns.org`); the Auth subdomain is SL-075 and shares the DNS plan. Keep `backup` private and without a public hostname.
- **Configuration:** update Worker bindings, environment variables and examples, CI and documentation to the storage map from SL-071.
- **Backend rewiring and object-key cleanup:** rewire every backend upload/read/delete path to the SL-071 storage interface, then replace opaque/random and client-filename-derived keys with stable, useful keys generated by the server from owning entity IDs and media purpose. Organize objects under predictable prefixes. Player images use the identity-scoped key `players/<player-id>.png`; do not nest or duplicate the shared portrait by division, season, or team. Before any bulk copy/upload, document the target bucket and exact key format for every media purpose, generate a complete source-to-target rename manifest, and run a dry-run report for unresolved owners, duplicate targets, and collisions. Port every existing object and database/config reference to its target key while preserving formats, HLS relative paths, and public/private behavior.
- **Gradual rollout:**
  1. Local (Wrangler fixtures).
  2. Staging buckets, verified through the real app on staging.
  3. Production, **one bucket at a time**:
     - copy/rename objects according to the SL-070 manifest, including existing random-name uploads and the `fresher-images` → `player-images` move;
     - verify counts, checksums, sampled reads, and old-key/new-key coverage;
     - rewrite the database URLs for that bucket in a forward migration with count guards;
     - switch the reads;
     - retain the old objects/path during the rollback window; only then retire the old path or source bucket.
- **Approvals:** each production step is an owner-approved action through the approved workflows. Existing media are preserved throughout, and rollback stays possible until each bucket is verified.
- **Backup:** the `backup` bucket stays private and server-only.

**Completion checks:**
- For every migrated bucket, counts, checksums and sampled reads match before and after.
- Every existing object has a reconciled target key; no upload flow uses a client-provided filename as its storage key. Player portraits resolve consistently across division/season/team roster contexts through the single identity-scoped key.
- Every backend media route and helper uses the shared storage interface for new uploads and existing-object reads, replacements, and deletes; no legacy direct-R2 path remains active after cutover.
- All `fresher-images` objects and references are verified in `player-images`; deprecate the old bucket only after no active code, configuration, database URL, or public link depends on it and the rollback window has elapsed.
- Media URLs work on the target domain.
- No database row or code path references a retired host.
- The website domain remains Pages.dev.
- Local and staging are verified before production.
- Every production step has the owner's approval on record.
- Rollback was possible until each bucket's verification completed.

**Usable in its own phase (rule R10):** no new capability. Every existing media flow (player portraits, team logos, news images, home video, share images) keeps working through the real UI on local, staging and production after each bucket's cutover.
