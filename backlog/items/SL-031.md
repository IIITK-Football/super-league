**Restated (2026-11-20, D-05 resolved):** one modular Hono Worker serves the API, so there is no separate gateway Worker and no internal service binding to design.

**Issue:** A browser calling a separate Worker origin would be cross-origin. The Pages site needs a tested path to the Worker on its own origin.

**Required outcome:** Route `/api/*` on the Pages origin to the Worker (a Pages Function or Cloudflare route, whichever SL-030 shows to be simplest), with no browser CORS policy. Keep `/api` behavior or a compatibility adapter until the final frontend migration. Stable auth, error and cache behavior for public routes.

**Completion checks:** Browser requests reach the Worker on the same origin locally and on staging; authorization headers pass through; public route responses have stable auth, error and cache behavior; the rollback path to the Next backend is documented.

**Usable in its own phase (rule R10):** not applicable (routing infrastructure).
