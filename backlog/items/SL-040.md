**Consolidated (2026-11-18):** this item now owns all division and season configuration on the Worker API. It absorbs:
- the division visibility and navigation-order part of SL-060;
- the configurable sections, labels, order and navigation part of SL-044.

SL-044 keeps the rules builder; SL-060 keeps the home page presentation. The first dictator flow shipped with SL-020 (create, edit, archive, current season, sections, mostly through direct Data API writes under RLS).

**Issue:**
- Division and season configuration is written straight to tables from the dashboard.
- Division ordering and temporary hiding are not exposed.
- Division branding is not editable.
- The public navigation and section list are still partly decided by frontend code rather than by `season_sections`.

**Required outcome:**
- **Configuration API:** Worker API endpoints and server-side validation for creating, editing, temporarily hiding, archiving and restoring a division or season, plus season ordering and current state, division branding, format selection (whose semantics are in SL-054), and enabled sections.
- **Sections and navigation:**
  - Per season: which sections exist, their labels, order, navigation visibility and settings.
  - Sections come from the shared modules: schedule/results, standings, teams/rosters/team builder, profiles, division fantasy, predictions/leaderboards, newsletter/articles, legends/archive, rules and registration.
  - Configuration can never expose an unauthorized operation.
  - A missing optional module does not break the shared experience.
- **Division visibility and order:** across the site's navigation and listings. Hiding is reversible and never deletes history.
- **Audit and port:** every change is recorded in the SL-027 history. Move the dashboard's direct writes onto the validated API and remove the direct-write policies they relied on.

**Completion checks:**
- Each division shares the same core API, and configuration drives the differences.
- Archived or hidden seasons and divisions stay available to dictators' historical views and are never confused with deletion.
- A division's public navigation and section list come from validated configuration.
- Hiding and reordering are reversible and consistent after cache refresh.
- Every configuration change is audited.

**Usable in its own phase (rule R10):** this item is not complete until a dictator, from the dictator dashboard:
- creates, edits, brands, hides, archives and orders divisions and seasons;
- configures each season's sections and navigation;

and visitors see the configured navigation and sections. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
