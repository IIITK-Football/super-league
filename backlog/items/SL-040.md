**Issue:** Current division names, pages, division branches, and supported feature sets are encoded across frontend and database code.

**Required outcome:** Add backend APIs and validation for create/edit/archive/temporarily hide division and season, season ordering/current state, configuration of enabled sections and division format, branding, rules, and visibility. Keep configuration editable by dictator users with an audit trail.

**Completion checks:** Each division shares the same core API; configuration drives differences; archived/hidden seasons remain accessible to dictated historical views and are not confused with deletion.

**Usable in its own phase (rule R10):** this item is not complete until the dictator creates, edits, hides, archives and orders divisions and seasons from the dictator dashboard (the first version ships with SL-020). The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
