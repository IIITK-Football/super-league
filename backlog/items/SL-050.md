**Issue:** Current live control is inside broad Admin Command surfaces and “Scorer” maps to admin. The user wants a shareable scorer dashboard without granting dictator status.

**Required outcome:** Define and implement a separate scorer-only workspace and API scope for explicitly assigned matches/divisions. Dictators can grant and revoke a scorer assignment, including an expiring invitation bound to the intended authenticated account; the invitation cannot grant dictator access. Include all match operations in one workflow: set score/goal, status/timer/minute, record goals/own goals, attach or revise scorer and assist, edit/remove mistaken events, cards, and final result correction.

Design the match workflow for phone use at the field: keep score, timer/status, teams, and recent events visible; use clear, thumb-friendly controls; make adding and correcting an event quick; and show connectivity and pending-sync status. Support offline entry for assigned matches by persisting a minimal match snapshot and a durable queue of event changes on the scorer's device. Give each queued action an idempotent identifier and sync it safely when the connection returns. Detect server-side conflicts and surface them for explicit scorer resolution; never silently overwrite newer match data. Recheck authorization and assignment when syncing.

**Completion checks:** A dictator can issue and revoke a scoped scorer assignment; invitations are bound to the intended authenticated account and expired/revoked invitations cannot be used. Scorer can perform every authorized match change, including after initial entry, and cannot manage users, teams/rosters, division settings, editorial content, or fantasy grading. The mobile workspace remains readable and operable on narrow screens; offline changes survive reloads, display pending state, sync idempotently, and expose conflicts for resolution without data loss. An audit trail records who changed what and when. Direct API and RLS tests enforce the same boundary.

**Usable in its own phase (rule R10):** this item is not complete until an assigned scorer opens a phone-usable match workspace and changes match data, and a dictator assigns and revokes scorers, in the existing frontend. The flow follows the current frontend patterns (no redesign), exposes the real authorized action, handles loading, empty, success and error states, and is verified through the real UI, API and database path (allowed and denied cases) locally and on staging. Phase 9 only consolidates and refines it.
