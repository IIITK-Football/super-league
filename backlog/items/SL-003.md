**Status:** Approved by owner 2026-11-16 — `docs/decisions/SL-003-role-capability-matrix.md`. Captain allow-list includes FUT rating and attributes; protected identity fields (roll number, email, name, account link) are off-limits. Owner decision 2026-11-16: FIVE roles (user, captain, scorer, editor, dictator). Editor = newsletter create/edit/publish only. Captain has an explicit field allow-list (team details/branding; FUT/presentation of existing players; no player create/remove/rename/account-link, no roll number/identity changes). Legacy `editor`→editor; legacy `admin`→user unless a reviewed per-person assignment is recorded BEFORE migration (never auto scorer/dictator).


**Issue:** The current `admin` value is shown as “Scorer” but has broad access, while `editor` remains in the schema and route model. No role currently describes the requested least-privilege scorer.

**Required outcome:** Define normal user, captain, scorer, editor, and dictator capabilities and role assignment scope. A normal user uses the public product and their own account. A captain may enter details for their assigned team, but cannot add, remove, rename, or otherwise manage player records. A captain may submit a lineup using existing players if the lineup workflow grants that capability. A scorer can change all match data and match events, and nothing outside match operations. A dictator can manage all data, configuration, assignments, and roles.

**Minimum intended boundaries:** A scorer can create/update/undo all match events and match state within their assignment; a captain can enter team details and submit a lineup from the existing player list but cannot change that list; a dictator can perform every management operation; a normal user can use public features and their own account/predictions.

**Completion checks:** The matrix names read/write actions for each entity and is the source for API authorization, RLS, and dashboard access tests. No “admin” alias silently grants scorer or dictator access.
