## Assignment

**Entry point.** Captain opens the assigned fixture's Lineup editor. Visitor opens the public match details.

### Flow and screen sketch

- Captain → assigned fixture → Lineup → private pitch draft with named slots, roster picker, server-based window notice, and Submit lineup.
- Dictator → fixture → edit and lock override. Visitor → public match → starting positions with team colors and inline FUT cards.

The captain screen shows the kickoff and submission state above the formation. Selecting a slot opens the filtered roster picker. Keep the draft and submission states visually distinct. On the public match, show each team’s formation or its missing-lineup state.

### Acceptance scenarios

1. Verify 5-a-side 1-2-2, 9-a-side 1-3-3-2, and 11-a-side 1-4-3-3, counting the goalkeeper as the first slot. Use existing roster memberships for that team entry. Reject duplicates, incomplete submissions and out-of-roster choices without changing the roster.
2. Let an assigned captain prepare a private draft before the window. The server accepts submission or changes to a submitted lineup at scheduled kickoff minus 30 minutes, and rejects captain edits at or after kickoff. A dictator can override the lock. Verify direct calls by other captains, scorers, ordinary users and guests cannot write lineups.
3. Each captain can see their own submission. Publish both to visitors and the other team when both submit. At kickoff publish whichever lineup was submitted and show a clear missing state for the other team. Never publish a private draft.
4. If the fixture is rescheduled before play, keep already-public lineups visible and recalculate the captain window using the new scheduled time. Verify that an edit outside the recalculated window is refused and the previous public lineup survives.

Keep the current match styling. See the [contributor issue](https://github.com/IIITK-Football/super-league/issues/186).
